# Ties 0.2 — "Your Mac already knows who they are"

Status: approved for implementation. Builds on the 0.1 spec (`2026-09-16-ties-design.md`); everything there still holds unless this document says otherwise.

## 1. Purpose

0.1 researches a contact from what the web says. 0.2 adds what *your own Mac* already knows about them — how you and the people in your chats address them, what they wrote in email signatures, what name they gave themselves on WhatsApp, what links they shared — and uses it three ways:

1. **Seeds** — more and better search queries (aliases, titles, companies).
2. **Verification** — local facts become evidence in the scorer, so the right online identity wins.
3. **Relationship** — when you last talked, how often, and a one-tap way to reach out.

It also makes research several times faster, and puts AI in the places where a good assistant would sit: judging candidates, grouping your network, drafting the message you were about to write.

## 2. What is *not* in 0.2 (and why)

- **No crowd-sourced names (GetContact-style).** That model uploads every user's address book to a server. Ties never uploads a contact. The local equivalent — how *you* and *your* chats address this person — is implemented instead (§4).
- **No LinkedIn phone/email verification.** LinkedIn shows contact details only to logged-in connections, and Ties never logs in anywhere. Phone and email verification comes from WhatsApp's self-set name, links the person shared themselves, and their email signatures (§4.4).
- **No reading of message *content* by cloud AI** unless the user turns that on per provider (§7.5). Local signals are extracted by code, not by a model, and stay on the Mac.
- **No new dependencies.** Still GRDB, SwiftSoup, PhoneNumberKit.

## 3. Sources

Every source is optional, off until granted, and shown on a new wizard step **Sources** (§8.1). Each has a `SourceStatus`: `unavailable` (app or file not present), `needsAccess` (Full Disk Access missing), `ready`, `error(String)`.

| Source | Where | Access | Reads |
|---|---|---|---|
| Contacts extras | `CNContact` nickname, note, phonetic names, postal addresses, related names, dates | already granted | aliases, honorifics, city/country (location evidence — makes the 0.1 `location` weight live) |
| Messages (iMessage/SMS) | `~/Library/Messages/chat.db` (read-only SQLite copy) | Full Disk Access | handles ↔ contact, group-chat names, how people address them, links they shared, last message date, message counts |
| WhatsApp Desktop | `~/Library/Group Containers/group.net.whatsapp.WhatsApp.shared/ChatStorage.sqlite` | Full Disk Access | self-set display name (push name), group names, links shared, last message date, counts |
| Mail | `~/Library/Mail/V*/**/*.emlx` found via Spotlight (`NSMetadataQuery` on author/recipient address) | Full Disk Access | signature blocks (title, company, phone, website, LinkedIn/X URLs), subjects, last mail date, counts |

Reading rules: always copy the SQLite file to a temp location before opening (WAL-safe, never locks the owning app); open read-only; never write to any source; cap work per person (Messages/WhatsApp: last 500 messages per handle; Mail: 50 most recent messages per address). Everything runs off the main actor in a `SignalCollector` actor with the same `AsyncStream<ScanProgress>` shape as the scanner, and shows as stages ("Reading your chats with Sara…").

Full Disk Access is requested by opening `x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles` with an inline instruction row; status is re-checked on each appearance by attempting to open the file.

## 4. Local signals

### 4.1 Model

```
signal                         -- one row per person; rebuilt by every collection
  personId PK
  aliases      JSON [String]   -- other names: nickname, WhatsApp push name, name used in chats/mail
  honorifics   JSON [String]   -- "Dr", "Eng", "Prof", "Sheikh", "دكتور", "مهندس", "أستاذ", …
  titles       JSON [String]   -- from signatures: "Senior Product Manager"
  companies    JSON [String]   -- from signatures and Contacts organization
  links        JSON [String]   -- URLs the person shared or signed with (canonical)
  phones, emails JSON [String] -- normalized values seen in signatures/handles not already in Contacts
  location     TEXT NULL       -- city/country from postal address or signature
  lastContact  REAL NULL       -- most recent message/mail either direction
  interactions INT             -- messages + mails in the last 365 days
  sources      JSON [String]   -- which sources contributed
  collectedAt  REAL
```

`ProbeInput` gains `signals: LocalSignals?`. `Person` is unchanged.

### 4.2 Extraction rules (code, not AI)

- **Honorific + name**: a token from the honorific list immediately before any of the person's names (given, family, alias) in a message written by *someone else* (not the user). Arabic and English lists; case- and diacritic-insensitive via `NameMatcher.normalize`.
- **Alias**: WhatsApp push name; Contacts nickname; the "From:" display name in their mail; a capitalised name that co-occurs with their handle in group chats where the user is not the author (≥ 3 occurrences).
- **Signature block**: last ≤ 8 non-empty lines of a mail body after the last `-- `, `Regards`, `Best`, `Thanks`, `تحياتي`, or the sender's name; parse lines for title-like phrases (`Title at Company`, `Title | Company`, `Title, Company`), phone numbers (PhoneNumberKit), URLs, and a line matching the person's name. Reject blocks with > 3 URLs (newsletters) or quoted-reply markers.
- **Links**: any `linkedin.com/in/…`, `x.com/…`, `github.com/…`, personal domains, in messages *sent by the person* or in their signature. Canonicalised with `ProbeFinding.canonical`.

### 4.3 Seeds

`SearchQueryBuilder` (both modes) gains queries from signals: `"<alias>" "<company>"`, `"<honorific> <name>"` (Arabic honorifics searched as written), and `"<title>" "<company>"` when the name is ambiguous (single-token name). Quick mode: at most one extra query; thorough: all.

### 4.4 Verification (scorer)

New `Evidence.Kind` cases and default weights (`ScoringWeights` grows accordingly):

| kind | weight | fires when |
|---|---|---|
| `selfLink` | 6.0 | candidate URL equals a link the person shared themselves or signed with |
| `selfName` | 2.0 | candidate display name matches an alias/push name (not the Contacts name) |
| `signatureTitle` | 2.0 | candidate headline contains a signature title (JW ≥ 0.85) |
| `honorific` | 1.0 | candidate headline/snippet contains a profession implied by an honorific (Dr → doctor/physician/PhD/dentist; Eng → engineer) |
| `location` (existing) | 1.5 | now reachable: signal or postal-address city matches |

`selfLink` alone reaches auto (6.0). `conflict` (−3) also fires when a signature title contradicts a candidate headline (different profession words, JW < 0.5) or the WhatsApp push name is a different full name.

### 4.5 Relationship

Detail view header gains a **Relationship** row: `lastContact` as "Talked 3 weeks ago" with the channel icon (Messages, WhatsApp, Mail), and a 5-segment strength bar from `interactions` (0, 1–4, 5–19, 20–99, 100+). Sidebar gets **Reconnect**: people with relevant profiles and `lastContact` older than 90 days, sorted by strength.

## 5. Faster research

- **Search pool**: `WebKitSearchPool` owns N `WebKitSearchBackend` web views (Settings › Research, default 2, max 4, icon `square.grid.2x2`). Queries are dispatched round-robin; each view keeps its own 2.5 s spacing with ±0.7 s jitter. Scanner concurrency = 2 × pool size (WebKit) or 6 (API engines).
- **Engine failover**: scrapable engines are DuckDuckGo, Bing, Brave, each a `WebKitSearchBackend` variant (URL template + result selector). A challenge on one engine moves that view to the next engine for 10 minutes instead of backing off. A spike task validates each engine's selectors before the feature is wired; engines that fail the spike ship disabled.
- **Skip the obvious**: people whose signals already produced a `selfLink` skip web search in quick mode (the page is fetched directly).
- **Per-person budget**: quick mode hard-caps a person at 25 s wall-clock; whatever probes finished are scored.

## 6. Sources in the wizard and the app

New wizard step **Sources** between Contacts and Select: a list of the four sources as rows — app icon (Contacts, Messages, WhatsApp, Mail via `NSWorkspace.shared.icon(forFile:)` of the installed app, SF Symbol fallback), name, a status glyph (`checkmark.circle.fill` green / `lock.fill` orange "Needs Full Disk Access" / `minus.circle` gray "Not installed"), and a toggle. One `Button("Open Privacy Settings")` when anything needs access. Continue is always enabled; sources off simply contribute nothing. Step dots become 9.

The Research step's stage line shows source stages first ("Reading your mail with Sara…"), then web stages. Review rows show "Known as" chips (`person.text.rectangle` icon + alias/honorific) and a `link` chip when a self-link verified the candidate. Settings › Sources mirrors the wizard step and adds "Collect again".

## 7. AI, where it helps

All features use the chosen provider (`AIProvider`), default on-device when available. Nothing runs without a user action except the smart lists refresh after extraction. Every AI-produced element is marked with `sparkle` and can be dismissed; none blocks the UI.

### 7.1 Candidate judge
After scanning, for each person with ≥ 2 pending candidates (or one pending below 3.0), the provider receives the candidates' public snippets plus the *public-safe* signals (aliases, titles, companies, honorifics — never message text) and returns `{candidateId, confidence 0–1, reason ≤ 90 chars}` (schema-constrained like extraction). The top pick gets a `sparkle` chip with the reason; the user still confirms. Runs as `Job.Kind.judge` with progress in the Review step footer.

### 7.2 Smart lists
After extraction, the provider groups the network into ≤ 8 lists from `occupation`/`canHelpWith` (`{name, systemImage, personIds}`), e.g. "Doctors", "Founders", "Engineers in Riyadh". They appear in the sidebar under a `sparkle` header, each with its icon. Refresh on demand (`arrow.clockwise`) or after a new extraction. Stored in `smart_list`.

### 7.3 Ask, better
The ask query is expanded once by the provider into ≤ 6 role/skill terms ("help with taxes" → accountant, CPA, tax advisor, bookkeeper) before hybrid search; the expansion is shown as removable chips under the field. Falls back to the raw query on any error, within 2 s.

### 7.4 Draft a message
Detail view action pill **Draft** (`sparkle.bubble`): a popover asks "What do you need?" (one field). The provider writes a ≤ 60-word message in the user's own register, learned from the user's last 20 messages *to that person* (on-device only; with a cloud provider the register sample is skipped unless §7.5 is on). Buttons: Messages, WhatsApp (`whatsapp://send?phone=…&text=…`), Mail — each opens the app with the draft prefilled; nothing is sent by Ties.

### 7.5 Privacy switch
Settings › Providers: "Let cloud AI see local signals" (default off). Off: cloud providers get public snippets and Contacts-level facts only; the judge, expansion and drafting run without signals; drafting uses no register sample. On-device Apple Intelligence always has access. The switch state is shown as a `lock`/`lock.open` glyph next to the provider tile.

### 7.6 Fact check
The extractor gains a second pass: each fact's `sources` snippets are re-sent with the fact, and the provider answers `supported: Bool` (batched, one call per person). Unsupported facts get a dotted underline and a `questionmark.circle` help "Not found in the sources"; they are excluded from smart-list grouping and from the `canHelpWith` search weight.

## 8. UI rules (unchanged, restated)

Icons and logos, not labels; no subtitles that repeat the title; `.snappy`; system materials; every new element has an SF Symbol: Sources `tray.full`, Messages `message.fill`, WhatsApp app icon, Mail `envelope.fill`, Known-as `person.text.rectangle`, Relationship `heart.text.square`, Reconnect `arrow.uturn.backward.circle`, Smart list `sparkle`, Judge `sparkle`, Draft `sparkle.bubble`, Search pool `square.grid.2x2`, Fact check `checkmark.seal`.

## 9. Data model changes

- `signal` (§4.1), `smart_list(id, name, systemImage, personIds JSON, createdAt)`, `judge(personId PK, candidateId, confidence, reason, providerId, judgedAt)`.
- `profile.facts` Fact gains `supported: Bool?` (nil = not checked).
- `Job.Kind` gains `collect`, `judge`.
- Migration `v2` adds the tables and the column; FTS content gains aliases and titles.

## 10. Privacy stance (addendum to 0.1 §10)

What Ties learns from your chats and mail stays on this Mac, with two deliberate exceptions, both of which are the feature working. First, searching: a name, an employer, a job title or another name someone goes by can appear in a web search, the same way a contact's name and company already did in 0.1 — that is how a person is found at all (§4.3 seeds). Second, the AI: with "Let cloud AI see local signals" switched off, a cloud provider is sent only what the address book already held; switch it on and it also sees aliases, titles, companies and honorifics (§7.5), plus the user's own last twenty messages to that person when a draft is asked for (§7.4). It is never sent a message anyone sent the user, a subject line, or the address book, and Apple Intelligence on this Mac sends nothing anywhere. Ties opens Messages, WhatsApp and Mail stores read-only, from a temporary copy, and never modifies them. Full Disk Access can be revoked at any time; Ties keeps working with what the web says.

## 11. Testing

- Collectors are tested against fixture SQLite files and `.emlx` files created by the tests (no real data), including: honorific detection in English and Arabic, signature parsing with three layouts, push-name alias, shared-link canonicalisation, the 500/50 caps, and WAL-copy behaviour.
- Scorer tests for every new evidence kind and the signature-title conflict.
- Search pool tests with a fake backend: round-robin, jitter bounds, failover after a challenge, concurrency derivation.
- Provider tests for judge/smart-list/expansion/fact-check schemas with the existing `FakeHTTP`.
- App: no automated UI tests; `docs/manual-test.md` gains a Sources section and an AI section.
